# Moon Code 0.2.0 发布说明

状态：待发布
日期：2026-07-27
最低 Kimi Code 版本：`>=0.29.2`

## 本次更新

### 次主力模型

- 设置页新增“次主力模型（实验）”，候选模型覆盖所有已配置 Provider。
- 次主力设置支持选择内置 Kimi、复用已有 Provider，或填写 Provider ID、协议类型、Base URL 与 API Key 后连接并获取模型列表。
- API Key 只经类型化 IPC 交给 Kimi 配置层，Moon Code 不回读、不展示，也不建立第二份凭据存储。
- 主 Agent 继续使用 primary 模型；新派生的 `Agent` / `AgentSwarm` 默认使用 secondary。
- Kimi Runtime 仍保留每次派生时显式选择 `primary` 或 `secondary` 的官方语义。
- 模型支持 effort 列表时，设置页只允许选择有效档位。
- Moon Code 显示当前 effective 配置、实验开关状态、配置方式和待重启状态。
- 保存过 Moon Code 覆盖后，可选择“使用 Kimi 原有配置”回到 Kimi 配置文件或启动环境提供的模型/effort。

### Kimi 0.29.2 兼容路径

Kimi `0.29.2` 已具备 secondary Core 能力，但该版本的公开 `/config` POST schema 尚未声明 `secondary_model`。Moon Code 不会发送会被静默丢弃的伪写入，也不会直接修改 `config.toml`。

对 Moon Code 自己启动的 managed/system Runtime，本版本使用 Kimi 官方配置面：

- `KIMI_SECONDARY_MODEL`
- `KIMI_SECONDARY_EFFORT`
- `KIMI_CODE_EXPERIMENTAL_SECONDARY_MODEL`

设置保存在 Moon Code 本机启动偏好中，仅用于下一次启动 Kimi Runtime；文件权限为 `0600`。保存或禁用后，设置页会提示用户确认重启。

### 禁用与恢复继承

“禁用并恢复继承主模型”不会删除 Kimi 配置文件中的 `[secondary_model]`。Moon Code 在自己启动的 Runtime 中设置 `KIMI_CODE_EXPERIMENTAL_SECONDARY_MODEL=0`，重启后新派生的子 Agent 恢复继承主 Agent 模型。

Kimi 的 `KIMI_CODE_EXPERIMENTAL_FLAG=1` master flag 优先级高于 secondary 专用开关。为保证禁用实际生效，禁用模式不会把父进程中的 master flag 传给该 Runtime；因此仅依赖 master flag 开启的其他实验功能也会停止。Kimi 配置中逐项开启的实验功能不受影响。

## Runtime 边界

- managed/system Runtime：可设置、禁用并由用户确认重启。
- shared/external Runtime：Moon Code 无法改变已有进程的环境；除非 Runtime 的公开 REST 契约声明写能力，否则保持只读。
- `max_output_size`：Kimi 没有 secondary 专用环境变量，仅在 Runtime REST 契约明确支持时开放。
- 重启会中断正在执行的任务并关闭当前 Session 连接，界面会在操作前提示。

## 兼容性与升级

- Moon Code 版本升级到 `0.2.0`。
- bundled Kimi Code 升级到 `0.29.2`。
- 最低支持版本为 `>=0.29.2`，不设置未来版本上限。
- secondary REST 写能力按当前 Runtime OpenAPI 动态探测，后续 Kimi 版本无需依赖硬编码版本号开放。

## 验证

- `pnpm check` 覆盖类型检查、常规测试和生产构建。
- `pnpm test:secondary-runtime` 使用临时 Kimi Home、临时 Workspace 和本地假 OpenAI 兼容服务，对真实 Kimi `0.29.2` Runtime 验证：
  - `Agent` 默认绑定 secondary；
  - `Agent` 显式 `primary` 覆盖；
  - `AgentSwarm` 新派生 worker 默认绑定 secondary；
  - 禁用实验开关后恢复 primary 继承；
  - secondary effort 环境覆盖实际进入请求；
  - 无效 secondary 模型和 effort 进入官方 Session warnings。
  - 无效 secondary 模型的派生错误保留官方配置来源提示。

该验收不读取用户凭据或 Session，不访问真实计费模型，也不修改用户 Kimi 配置。
