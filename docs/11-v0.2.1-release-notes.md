# Moon Code 0.2.1 发布说明

Moon Code 0.2.1 补齐模型服务管理和跨 Provider 子 Agent 模型选择，并继续保持 Kimi Runtime 是唯一配置与凭据数据源。

## 模型服务管理

- 设置页可编辑自定义 Provider 的名称、协议、Base URL、API Key 和默认模型别名。
- 使用 Kimi 0.29.2 官方 `PUT /api/v1/providers/{provider_id}` 更新 Provider，并保留现有模型元数据。
- 使用官方 `DELETE /api/v1/providers/{provider_id}` 删除 Provider 和对应模型别名，删除前提供明确确认。
- 内置 Kimi Provider 在 Renderer 和 Main 两层均禁止编辑或删除；账号状态继续通过官方 OAuth 路径管理。
- Runtime 未声明 Provider 管理路由时，界面保持只读并解释兼容性限制，不直接修改 `config.toml`。

## 子 Agent 模型

- 子 Agent 模型可以从任意已连接 Provider 的模型目录中选择。
- 选择通过现有 typed IPC 和 Kimi 官方 Runtime 环境/Config 能力保存，只影响之后新建的 Agent 和 AgentSwarm。
- 删除正在使用的 Provider 时会提示其子 Agent 模型设置将失效。

## 验证与分发

- `pnpm check` 覆盖类型检查、386 项通过的自动化测试和生产构建。
- macOS 产物仍为未签名 DMG；首次打开方式与限制见[最小运行与未签名分发](./08-minimum-run-and-distribution.md)。
